# 学术模式开关 · dsh-academic-switch

> 输入框旁一枚深蓝色开关。打开后，每个来源核查三遍，每份交付检查三遍逻辑，推理强度与输出预算拉到模型上限。

- **关**：一切照旧，插件只在后台待命。
- **开**：从下一条消息起，每一步模型调用都推到该模型支持的上限，系统提示里加入一段「学术纪律」。

## 安装

在 DeepSeek Harness 的 **插件 → 添加插件** 里填入本仓库地址，点 **安装**，装好后点 **立即启用**：

```
https://github.com/FelixJiashengFu/dsh-academic-switch
```

输入框左侧随即出现带学位帽图标的「学术」开关。升级：在插件页卸载后，用同样的方式重新安装。

本地开发：克隆本仓库后，在 **添加插件** 里填本目录的绝对路径，或让 agent 调用插件管理器（不要手改 profile 的 `package.json`）：

```
plugin_manager action=install_bundle target=<本目录绝对路径>
```

卸载：在插件页卸载，或 `plugin_manager action=remove_bundle target=dsh-academic-switch`。

## 它做了什么

| 杠杆 | 实现 | 效果 |
| --- | --- | --- |
| 学术纪律 | `systemPrompt.section` 注册一段长提示（`order: 650`，`interpolate: false`） | 三遍资料核查、三遍逻辑检查、多方面取证、统一的交付标准 |
| 推理强度 | `agent/request` 瀑布里读取 `llm.resolveModelInfo()`，把 `reasoningEffort` 换成该路由声明的最强一档 | 思考更久，更少跳步 |
| 输出预算 | 同一处把 `maxTokens` 抬到模型的 `defaultMaxTokens`；已配置更大的值时保留原值 | 不因默认输出上限被截断 |
| 视觉 | 关闭时中性描边；开启时深蓝渐变，界面主色转为学术蓝 | 一眼看出当前处于学术模式 |

## 学术纪律

全文在 [`lib/prompt.js`](lib/prompt.js)，约 3,100 个字符，分六章：

1. **底线**：无来源不陈述；绝不编造文献、DOI、数据或核查过程；分清事实、推断、观点与推测；关键结论标注置信度；前提有误先指出。
2. **多方面查找资料**：先拆解问题并列出中英文检索词；关键问题至少覆盖五类来源中的三类（一手研究、综述与教材、官方与标准、学术数据库、数据与代码）；正反都查；二手转述追到原始出处；依据全文而非摘要；关注时效；关键结论至少两个独立来源。
3. **资料真实性三遍核查**，每个被引用的来源都要过：
   - 第一遍 · 存在性与元数据：DOI、arXiv 编号、PMID、ISBN 或官方网址能打开，题名、作者、年份、卷期页码与版本逐项核对；
   - 第二遍 · 内容一致性：回到原文定位页码、图表或条款，确认数字、引语与观点完全一致，没有断章取义；
   - 第三遍 · 独立交叉与可信度：独立来源交叉验证，查撤稿与更正，评估证据等级与利益冲突。
4. **逻辑严谨性三遍检查**，交付前完成：
   - 第一遍 · 结构：论点 → 证据 → 结论链条完整，定义一致，结论不越过证据范围；
   - 第二遍 · 推理与计算：逐条排查常见谬误，数值与统计量重新计算；
   - 第三遍 · 对抗审查：以审稿人身份写出最可能被攻击的三点并回应。
5. **交付标准**：结论摘要 → 论证与证据 → 局限 → 参考文献 → 核查记录。参考文献未指定格式时，中文默认 GB/T 7714—2025（现行版，2026-07-01 起实施），英文默认 APA 第 7 版。
6. **诚实与边界**：没做成的核查如实写明影响；同一动作失败两次就换思路；破坏性或对外操作仍需确认。

三遍用的是三种不同的方法，而不是把同一个检查重复三次：三种方法各自能发现另外两种发现不了的错误（不存在的文献、引错的数字、已撤稿的研究；断裂的论证链、算错的统计量、经不起反驳的结论）。

## 设计说明

1. **段落位置**。`@deepseek-ai/dsh-system-prompt` 按 `order` 升序排列段落，并为自带段落保留了这些位置：身份 −1000、部署人格前缀 0、计划模式政策 500、团队政策 600、工具说明从 1000 起。650 让学术纪律排在两段政策之后（计划模式仍然决定什么可以执行），排在所有工具说明之前（纪律先于工具用法被读到）。
2. **不换模型**。只在当前选中的模型上把预算拉满，不改 provider 和 model，不破坏会话的模型粘性。
3. **只请求模型真有的档位**。`reasoningEffort` 取自适配器声明的候选，不会塞入会被拒绝的值；模型没有推理档位时只调整 `maxTokens`。
4. **状态路由只接受本机同源请求**。`/plugins/dsh-academic-switch/state` 只接受回环地址；POST 必须是 `application/json`，所以其他网站无法用表单提交悄悄打开开关；带有不同源 `Origin` 的请求会被拒绝。
5. **失败不致命**。提示词服务晚于插件就绪或中途重载时，段落会自动重新挂载；查询模型能力失败时，这一步按原配置发送，错误显示在开关的悬浮提示里。

与 [豪霸模式](https://github.com/FelixJiashengFu/dsh-haoba-mode) 的关系：学术模式已经包含「推理强度与输出预算拉满」，两者不需要同时打开；同时打开也不冲突，两段提示词各自生效。

## 状态与接口

开关状态保存在 `~/.dsh/academic-switch.json`（`{ "enabled": true, "title": "学术模式" }`），重启后自动恢复。

回环 HTTP 路由 `GET|POST /plugins/dsh-academic-switch/state`：

```json
{ "ok": true, "enabled": true, "lastError": null,
  "applied": { "provider": "…", "model": "…", "reasoningEffort": "max", "maxTokens": 65536, "at": 0 } }
```

POST 请求体为 `{ "enabled": true }` 或 `{ "enabled": false }`。`applied` 是最近一次真正改过的调用参数，开关的悬浮提示会显示它。

## 结构

```
package.json        dsh.bundle.patch + dsh.client（把 lib/client.js 送进 Web 客户端）
cordis.patch.yml    Host 半边的挂载行
lib/protocol.js     路由、段落名与位置、状态文件名（浏览器半边复制路由常量）
lib/prompt.js       学术纪律全文
lib/index.js        Host：状态持久化、回环路由、agent/request、systemPrompt 段落
lib/client.js       浏览器：深蓝开关（只依赖 react，无 JSX、无 import）
locale/zh.json      插件市场里的中文名与简介
locale/en.json      英文名与简介
icon.svg            学位帽图标
test/               node:test 测试：Host 行为、浏览器半边注册与渲染、提示词完整性
```

## 测试

需要 Node.js 20 或更高版本，无需安装依赖：

```
npm test
```

测试用一个假的 Cordis 上下文运行插件的真实代码，覆盖：开关与状态持久化、段落只注册一次、提示词服务晚到或重载时的重新挂载、推理强度与输出预算的选择规则、重启恢复、路由的来源与请求体校验，以及浏览器半边的注册位置与初始渲染。

## 代价

开启后每一步请求都会携带约 3,100 个字符的纪律段落，推理也会更长；核查记录会让回复变长。这是这个模式的设计目的：用 token 和时间换可核查、可复现的结果。不需要时把开关关掉即可，状态立即生效，无需重启。
